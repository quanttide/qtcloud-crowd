# 人：执行方管理

> 众包云三视角之「人」——管理执行方（渠道/代理/实训基地成员）

## 想象中的样子

```
执行方列表（认证状态一目了然）
├── 准入审核队列：待审核申请 → 审核 → 认证通过/拒绝
├── 执行方档案：认证等级 + 接单记录 + 交付质量
└── 信用分（执行率/验收通过率沉淀）——高信用优先接单
```

- 注册申请自动归队，审核人一键通过/打回（附理由）
- 档案随每次交付自动更新（不用手改）
- 信用分驱动接单排序（激励高质量交付）

## 最精简的样子

```
执行方名单 + 认证状态
└── 一个动作：认证（待认证 → 已认证）
```

- 不做的：信用分/接单记录/自动更新（远期）
- 先做的：**名单 + 认证状态**（知道谁是可信执行方就够了）

## 精简理由

认证是唯一"不说清就不能往下走"的动作——接单前必须先知道对方是谁。记录与信用是沉淀出来的，不是先设计的。
