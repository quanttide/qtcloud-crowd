# 量潮众包使用指南

> 面向：需求方（发单）与执行方（接单）
> 定位：标准任务、标准交付、标准验收——验收准则兜底

## 基本流程

```
需求方发单 → 执行方接单 → 执行交付 → 验收 → 结算 → 信用沉淀
```

## 需求方：发单

1. **拆解需求**：把需求拆成标准任务（任务 = 交付标准 + 验收准则清晰可判）
2. **发布任务**：填写任务说明、交付物、验收准则、报酬
3. **准入筛选**（可选）：设置接单条件（如认证渠道/代理等级）
4. **等待接单**：执行方在标准内竞价/认领

### 任务要素（参考真实示例）

```
- 业务 / 类别 / 状态（待认领）
- 任务背景（为什么做）
- 任务内容（可验收的条目清单）
- 任务输入（报名后提供——原始数据/格式章程）
- 参考链接
```

## 执行方：接单

1. **注册准入**：成为认证执行方（渠道/代理/实训基地成员）
2. **认领任务**：标准内竞价或直接认领
3. **执行交付**：按任务内容逐条完成，产出可交付物
4. **响应反馈**：验收不通过时按反馈修改

## 验收与结算

| 环节 | 规则 |
|------|------|
| **验收** | 按验收准则判定（清晰可判——不靠感觉） |
| **结算** | 按量潮标准结算（验收通过后） |
| **信用沉淀** | 执行率/验收记录沉淀为信用——影响后续接单优先级 |

## 场景示例

### 招聘考核任务（真实案例）

需求方（量潮）：发布"第二大脑创建插件"任务——把创建第二大脑的对话流程接入资产云整理为插件。

```
类别：招聘考核
状态：待认领
任务内容：
  1. 理解现有对话流程与格式章程
  2. 接入资产云，整理为插件/可复用配置
  3. 输出非技术用户使用说明
  4. 完成一轮测试并记录
输入：原始对话导出 + 格式章程（报名后提供）
```

执行方（候选人/实训成员）：认领 → 完成 4 条任务 → 验收 → 实际产出代替答卷。

## 原则

1. **站点只做信息展示，不是交易平台**——交易走标准流程（任务/交付/验收）
2. **验收准则兜底**——任务说不清验收 = 不发单
3. **实际产出代替答卷**——考核/合作看产出，不看来头
