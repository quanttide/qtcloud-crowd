# 事：任务审核

> 众包云三视角之「事」——任务从发单到验收的生命周期

## 想象中的样子

```
任务列表（状态跟踪）
├── 待认领 → 进行中 → 待验收 → 已完成/已关闭
├── 审核：验收准则不清晰 → 打回补全
├── 归档分类（招聘考核/业务任务/运营任务）
└── 验收裁决：通过 / 打回修改（附反馈）
```

- 每个任务有清晰的状态流
- 审核是第一道关：说不清验收 = 不发单
- 裁决按准则执行（不靠感觉）

## 最精简的样子

```
任务列表 + 验收结果
└── 两个动作：发布（审核通过后）/ 验收（按准则判通过或打回）
```

- 不做的：状态流转细分/归档分类（远期）
- 先做的：**任务能不能发（审核）+ 交付算不算过（验收）**——两个判断点

## 精简理由

任务的本质是两个判断：**能不能发**（验收准则清晰吗）和**算不算过**（交付达标吗）。中间的状态流转是管理粒度，不是必须。
